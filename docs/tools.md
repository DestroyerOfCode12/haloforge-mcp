# Tool reference

HaloForge MCP defines 450 tools. This file is generated by `npx tsx scripts/tools-doc.ts`; do not edit it by hand.

Which tools are registered depends on the safety settings: read tools always; create and update tools when an instance is in `write` or `full` mode; delete tools only in `full` mode with `HALO_DISABLE_DELETE=false`. `HALO_TOOLS` and `HALO_TOOLS_EXCLUDE` narrow the list further.

Every tool also accepts `instance` (string, optional): the configured instance to use. The default is the first configured instance or `HALO_DEFAULT_INSTANCE`. `halo_config_copy` writes to `target_instance` instead.

## Higher level and general tools

### halo_tickets_sla_detail

Get SLA, first response, resolution time and satisfaction detail for a single ticket by ID. Returns a curated subset of timing and SLA fields rather than the full ticket object (which has 1,000+ fields and routinely exceeds output limits). Halo permission: User, Ticket Read.

Access: read.

| Argument | Type | Required | Description |
|---|---|---|---|
| `id` | integer | yes | The ticket ID |

Example:

```json
{
  "id": 1001
}
```

### halo_api_request

Send a request to any Halo API path (relative to /api) when no dedicated tool exists. GET is always allowed. POST is allowed only when the instance is in write or full mode, and DELETE only in full mode with delete enabled. POST bodies are sent as given (Halo upserts usually expect a list).

Access: read.

| Argument | Type | Required | Description |
|---|---|---|---|
| `method` | "GET" or "POST" or "DELETE" | no | HTTP method (default GET) |
| `path` | string | yes | Path relative to /api, for example /TicketType/5 or /Lookup |
| `query` | object | no | Query parameters |
| `body` | any | no | JSON body for POST |
| `fields` | list of string | no | Return only these fields |

Example:

```json
{
  "method": "GET",
  "path": "/Lookup",
  "query": {
    "lookupid": 41
  }
}
```

### halo_ticket_type_layout_set

Change a ticket type's layout: add fields, move them between groups, change visibility or restriction flags, reorder, or take fields out (the field itself is never deleted). Fields can be named instead of using IDs. Every other field is kept. Use dry_run: true to see the diff first.

Access: write; supports dry run.

| Argument | Type | Required | Description |
|---|---|---|---|
| `ticket_type_id` | integer | yes | Ticket type ID |
| `changes` | list of object | no | Changes to fields in the layout (TicketType.fields) |
| `order` | object | no | Put these layout fields in this order, reusing their current sequence slots |
| `user_panel_changes` | list of object | no | Changes to the user panel (TicketType.userfields) |
| `dry_run` | boolean | no | Preview only: read the current record and return a before and after diff without saving |
| `merge` | boolean | no | Merge nested arrays into the current record by match key (default true). False sends data exactly as given |
| `replace_arrays` | list of string | no | Nested array keys to replace as given rather than merge |
| `full_object` | boolean | no | Send the complete current record with the change applied (default false: send id, changed keys and complete nested arrays) |
| `show_payload` | boolean | no | Include the exact payload in the result |

Example:

```json
{
  "ticket_type_id": 12,
  "changes": [
    {
      "field_name": "MCP TEST | Reason",
      "group_name": "Details",
      "seq": 4,
      "techdetail": 1
    },
    {
      "fieldid": 205,
      "remove": true
    }
  ],
  "order": {
    "fields": [
      "summary",
      "details",
      "MCP TEST | Reason"
    ]
  },
  "dry_run": true
}
```

### halo_dashboard_build

Access: write; supports dry run.

|---|---|---|---|

| `settings` | object | no | Any other dashboard values to send as given |

### halo_config_export

Export configuration to JSON files, one file per object, grouped by resource, with a manifest. Choose areas or resources, or export all configuration. Sensitive values are masked. Files go under the export folder (HALO_EXPORT_DIR, default ./exports).

Access: read.

| Argument | Type | Required | Description |
|---|---|---|---|
| `areas` | list of string | no | Areas to include: Tickets and layout, Workflow and automation, Service levels, People and structure, Service catalogue and portal, Assets and CMDB, Reporting, Other configuration, or all (default: all configuration) |
| `resources` | list of string | no | Individual API resources to include, for example TicketType |
| `include_data` | boolean | no | Also include record like resources (agents, users, clients, sites, articles and so on) when selecting by area |
| `max_per_resource` | integer | no | Maximum records per resource (default 1000) |
| `folder` | string | no | Folder inside the export folder (default <instance>_<timestamp>) |
| `details` | boolean | no | Read each record in full with includedetails (default true; slower but complete) |

Example:

```json
{
  "areas": [
    "Reporting"
  ],
  "folder": "trial_reporting"
}
```

### halo_config_compare

Compare configuration between two instances, or between an export folder and an instance. Records are matched by name; the result lists, per resource, what is missing from the target, what exists only in the target and what differs (changed field paths). IDs, GUIDs and dates are ignored.

Access: read.

| Argument | Type | Required | Description |
|---|---|---|---|
| `source_instance` | string | no | Instance to compare from |
| `source_export` | string | no | Export folder (inside the export folder) to compare from, instead of an instance |
| `target_instance` | string | yes | Instance to compare against |
| `areas` | list of string | no | Areas to include: Tickets and layout, Workflow and automation, Service levels, People and structure, Service catalogue and portal, Assets and CMDB, Reporting, Other configuration, or all (default: all configuration) |
| `resources` | list of string | no | Individual API resources to include, for example TicketType |
| `include_data` | boolean | no | Also include record like resources (agents, users, clients, sites, articles and so on) when selecting by area |
| `max_per_resource` | integer | no | Maximum records per resource (default 1000) |
| `details` | boolean | no | Compare full records with includedetails (default true) |
| `ignore_fields` | list of string | no | Extra field names to ignore |
| `max_paths` | integer | no | Changed paths to list per record (default 20) |

Example:

```json
{
  "source_export": "trial_reporting",
  "target_instance": "prod",
  "areas": [
    "Reporting"
  ]
}
```

### halo_config_copy

Copy configuration objects from one instance to another, for example a report group with its reports plus a dashboard. References (report groups, teams, agents, statuses, fields, reports in dashboard widgets and more) are mapped by name. Dry run by default: returns the full plan without saving. Pass dry_run: false to apply; this is refused while any reference is unresolved.

Access: write; supports dry run (dry run by default).

| Argument | Type | Required | Description |
|---|---|---|---|
| `source_instance` | string | yes | Instance to copy from |
| `target_instance` | string | yes | Instance to copy to |
| `items` | list of object | yes | Objects to copy |
| `include_dependencies` | boolean | no | Also copy reports used by dashboards and the groups of copied reports (default true) |
| `include_group_reports` | boolean | no | When copying a report group, also copy its reports (default true) |
| `on_existing` | "skip" or "update" | no | When the target already has an object of the same name: skip it (default) or update it to match |
| `allow_unresolved` | boolean | no | Apply even if some references could not be mapped (they keep the source ID) |
| `dry_run` | boolean | no | Default true. Pass false to apply the plan |

Example:

```json
{
  "source_instance": "trial",
  "target_instance": "prod",
  "items": [
    {
      "resource": "ReportGroup",
      "name": "MCP TEST | Service desk"
    },
    {
      "resource": "DashboardLinks",
      "name": "MCP TEST | Service desk"
    }
  ]
}
```

## Resource tools: common arguments

Each resource has up to four tools. The arguments below are shared; some resources add filters, listed in the next section.

### `halo_<resource>_list`

List or search <resource> records. Supports paging (or all_pages), sorting, filtering and choosing fields. Halo permission: Agent.

| Argument | Type | Required | Description |
|---|---|---|---|
| `page_size` | integer | no | Results per page (max 100, default 50) |
| `page_no` | integer | no | Page number (default 1) |
| `order` | string | no | Field name to sort by |
| `orderdesc` | boolean | no | Sort descending |
| `search` | string | no | Free text search string |
| `pageinate` | boolean | no | Enable pagination (default true) |
| `all_pages` | boolean | no | Fetch every page and return all records (up to max_items) |
| `max_items` | integer | no | Maximum records to return when all_pages is true (default 1000) |
| `fields` | list of string | no | Return only these fields (dot paths allowed, for example 'fields.fieldid') |
| `extra_params` | object | no | Any other Halo query parameters to send as given, for example { "client_id": 12 } |

Example (halo_fieldgroup_list):

```json
{
  "fields": [
    "id",
    "name"
  ],
  "all_pages": true,
  "max_items": 500
}
```

| Argument | Type | Required | Description |
|---|---|---|---|
| `id` | integer or string | yes | The field group ID |
| `includedetails` | boolean | no | Include related sub objects in the response |
| `fields` | list of string | no | Return only these fields (dot paths allowed, for example 'fields.fieldid') |
| `extra_params` | object | no | Any other Halo query parameters to send as given, for example { "client_id": 12 } |

Example (halo_fieldgroup_get):

### `halo_<resource>_upsert`

Create or update <resource> records. Pass one object or a list (sent in one API call). Include 'id' to update; omit it to create. Updates read the current record first and merge nested arrays so nothing is lost; use dry_run: true to see a field by field diff without saving. Halo permission: Admin.

| Argument | Type | Required | Description |
|---|---|---|---|
| `data` | object or list of object | yes | The field group record, or a list of up to 100 records. |
| `dry_run` | boolean | no | Preview only: read the current record and return a before and after diff without saving |
| `merge` | boolean | no | Merge nested arrays into the current record by match key (default true). False sends data exactly as given |
| `replace_arrays` | list of string | no | Nested array keys to replace as given rather than merge |
| `full_object` | boolean | no | Send the complete current record with the change applied (default false: send id, changed keys and complete nested arrays) |
| `show_payload` | boolean | no | Include the exact payload in the result |

Example (halo_fieldgroup_upsert):

```json
{
  "data": {
    "id": 3,
    "fields": [
      {
        "fieldid": 205,
        "seq": 2
      },
      {
        "fieldid": 206,
        "_remove": true
      }
    ]
  },
  "dry_run": true
}
```

### `halo_<resource>_delete`

Delete a <resource> by ID. Only available when the instance is in full mode and HALO_DISABLE_DELETE=false. Halo permission: Admin.

| Argument | Type | Required | Description |
|---|---|---|---|
| `id` | integer or string | yes | The field group ID to delete |

Example (halo_fieldgroup_delete):

```json
{
  "id": 3
}
```

Upsert notes: include `id` to update and omit it to create; a list sends one API call. Nested arrays are merged by match key (`_remove: true` takes an item out); `merge: false` sends data as given. Updates that change nothing are skipped. Every saved write is recorded in the audit log.
